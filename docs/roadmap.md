# Harness 实施路线图

更新日期：2026-11-04。本文是计划，不代表已完成实现或验证。职责以仓库根 `AGENTS.md` 为准。

## 目标

作为 Host 运行时加载的动态库插件提供 agent 编排。CLI 与 HomeWorld 通过 Host 使用插件，不直接编译依赖或加载 harness。

## 实施顺序

1. 保持独立插件包与 C ABI 边界，明确插件版本、宿主 ABI 和所需能力，适配 Host 独立发布链。
2. 定义任务标识、状态、事件、结果和取消契约，使 CLI 与 HomeWorld 能展示同一任务生命周期。
3. 完善执行过程持久化，区分运行转录与恢复状态，明确异常中断后的数据完整性。
4. 实现恢复策略，处理工具副作用的不确定窗口；通过幂等键或状态核对避免重复执行已完成的写操作。
5. 依据实际任务需求加入长期记忆接口，支持来源、作用域、检索、修改、删除和上下文预算。

## 验收标准

- Host 无需安装 harness 即可运行；安装后通过稳定 ABI 加载和调用。
- 消费者可以发起任务、观察工具事件、取消执行并查看结果。
- 恢复策略明确处理已执行但结果尚未落盘的工具调用，不将消息重放等同于安全恢复。
- 长期记忆与运行记录、家庭业务资料明确分离；不绑定 HomeWorld 数据库表，不越过用户或家庭权限边界。

## 依赖与不做事项

先完成 Host 独立服务、发布契约与消费者适配，再扩大 agent 产品范围。Harness 不接管工具沙箱、家庭身份或消费者进程管理。

长期记忆的存储和检索选型另行评估，不预设向量数据库为基础依赖。当前仅编写代码和文档，构建、测试、启动与发布待用户要求。
